## 0. 我理解的目标（请先确认这一节）

**一句话**：把实验面板右侧的「4 张横向切换卡片 + 底部一次性解锁的测量题 + 第 0 步弹出层 + 计算卡片弹窗」，改成**一条从上往下走的轨道**。任何时刻只有**当前这一步**是视觉重心；这一步需要什么图（面包板透视、芯片内部、电路图、电表接法、KVL 分步推导……），就**在这一步里**长出来；这一步做完，它连同它的图一起折叠成一行。

我理解的你的出发点：

1. **ADHD 需要的是强结构，不是碎片。** 现在的问题不是“内容太长”，而是“不知道下一步该看哪里”：横着切卡片（X 轴）、卡片里竖着走步骤（Y 轴）、再弹层（Z 轴），视线在三个方向上跳。
2. **从上往下一路看下来**最符合直觉。不要左右切、不要锁图标、不要“往下又往右”。
3. **要有重心**：不是每个块都戴边框抢注意力。进度只用一根灰色细条 + `3 / 7` 这样的小字，不用一排像按钮的数字胶囊。
4. **“搭 → 测 → 想明白”在同一个地方闭环**：测量题不要堆到最后统一考，也不要让人测两遍（现在 LM358 第 5 步测过一次，测量题又测一次）。
5. **Just-in-time 的图**（第 3 轮的补充，也是原型第二版的核心）：图和推导不是没有，而是**按需出现在需要它的那一步**，用完就收。

不是这次要做的：不改电路仿真本身、不改题库内容、不改 World 划分（`course/worlds.json`）、不改任何课程 / 实验的 id 和文件名（本地进度、交叉引用、e2e 都靠它们）。

### 2.2 十条规则

1. **一个焦点**：只有当前节点有 `2px` 深色描边和阴影（复用 `.td-sec.active` 的样式）。
2. **过去折叠成一行**：`✓ 序号 标题` + 右边一个**结果胶囊**（刚测出的数，或“已搭好”）。点一下展开回看，图和推导都还在。
3. **未来只露标题**：灰字 + `○`，不可点，不画锁、不画虚线框。让人知道“还有几步”，但不暴露内容。
4. **没有横向卡片**。“试一试 / 想明白 / 动手做 / 带走”不再是标签页，而是节点的**类型**，只体现在节点左上角的小眉题（eyebrow）颜色上。
5. **没有底部题库**。每道测量题放进它所属的那一步；一个读数只测一次。
6. **图按需出现**（§3 的内嵌块）。一个节点**最多一个大块**（图 / 拆解 / 推导），否则拆成两个节点。
7. **节点数 5–9**。分步课程里，连续的 1–4 个搭建步骤可以合成一个节点（节点里是一个带勾的小清单，每项仍有自动检查）。
8. **前进的条件写在按钮上**：`检查这一步 ✓` / `核对读数` / `下一步 ↓`。完成后自动展开下一节点，平滑滚动到它的顶部。
9. **原理图有固定的家**：顶部抽屉。不再跟着文字滚走。
10. **弹层全部取消**：第 0 步拆解、计算卡片，都变成内嵌块；“看完整拆解 ↗”“打开计算器 ↗”作为块底部的一行小链接，去独立页面（`#/inside`、`#/calc` 保留不变）。

### 2.3 节点类型（eyebrow）

| 类型 | 眉题 | 完成条件 | 来自原来的 |
|---|---|---|---|
| `look` 看 | 🔍 先看一眼 | 点「下一步」 | 第 0 步拆开看（只保留外形 / 引脚层，见 §2.4） |
| `build` 搭 | 🔧 动手搭 | 本节点里所有步骤的 `check` 通过 | 分步课程的 `steps`；实验的“照目标电路图搭”（用整体电路检查） |
| `measure` 测 | 📏 测一测 | 本节点的测量题都答完（含 Q4 的“3 次后放行”） | `measurements` |
| `think` 想 | 💡 想明白 | 点「下一步」；如果带推导块，揭开到最后一步 | `explain` 卡片 |
| `wrap` 带走 | 🎒 带走 | 无（最后一节点，显示“下一课 →”和“趁热练理论题”） | `wrap` 卡片 |

### 2.4 “先拆开”和“先动手”的冲突怎么处理

`docs/INSIDE.md` 说“每遇到一个新东西，先拆开，再动手”；卡片写法说“先动手、先看现象（可以故意做错），再讲原因”。现在用第 0 步弹层硬插在最前面，两者打架（例：1.1 的拆解一上来就把“金属条”讲完了，后面的“先插错一次”就没有悬念了）。

**规则**：拆解按层拆开用——
- `look` 节点只放拆解的**外形 / 引脚层**（怎么拿、哪只脚是哪只）：这是动手的前提，不剧透现象。
- **透视 / 内部 / 等效电路层**放进后面解释现象的那个 `think` 或 `measure` 节点里，作为内嵌块（例：LM358 的“内部三级”出现在“输出为什么顶不到 9 V”那一步）。
- 一课没有新器件（`registry.ts` 里没有挂这课）就没有 `look` 节点。

## 4. 工程设计

### 4.1 文件格式：`rail`（向后兼容）

在 `breadboard-challenge/1` 里加一个可选顶层字段 `rail`，**取代** `cards`（两者不能同时写，校验器检查）：

```json
"rail": [
  { "kind": "look",    "title": "认识 LM358",   "text": ["…", "![](inside:lm358#1)"] },
  { "kind": "build",   "title": "接电源，插芯片", "text": "…", "steps": 3 },
  { "kind": "build",   "title": "电位器接 IN+",  "text": "…", "steps": 1 },
  { "kind": "measure", "title": "不接反馈",      "text": ["…", "![](inside:lm358#3)"], "steps": 1, "measure": ["open"] },
  { "kind": "think",   "title": "放大十万倍的裁判", "text": ["…", "![](derive:gain)"] },
  …
  { "kind": "wrap",    "title": "带走", "text": ["…"], "practice": ["opamp"] }
],
"derivations": { "gain": { "steps": [ "…", "…", "…" ], "check": { "answer": 6.3, "unit": "V" } } }
```

- `steps`：和 `cards` 一样，节点按顺序领取顶层 `steps`，加起来等于步骤总数。
- `measure`：这个节点放哪几道测量题（id）。**每道测量题必须且只能出现在一个节点里**（校验器检查）。
- **兼容层**：没有写 `rail` 的旧文件，渲染器自动把 `cards` 转成轨道（`try` → 若干 `build`、`explain` → `think`、`build` 卡片 + 全部测量题 → `build` + 一个 `measure` 节点、`wrap` → `wrap`）。所以**第 1 期上线当天 85 个面板全部能用新界面**，之后再一课一课手工精排。
- 测量题的 id、题目文字、期望值、`set`，以及本地进度的存储键都**不改**——已经答过的题，换了界面仍然是答过的。

### 4.2 渲染器

新组件 `src/ui/Rail.tsx`（替代 `Cards.tsx` 在 `Panel.tsx` 里的位置）：

- `RailProgress`：顶部 3px 进度条 + `n / N`；右边缘刻度列。
- `RailNode`：三种状态 `past / active / future`；`past` 的结果胶囊取自本节点最后一个读数或“✓ 已搭好”。
- `TargetDrawer`：目标原理图抽屉（sticky），默认收起；第一个 `build` 节点出现后才可展开（保留“不提前剧透”的意图）。
- 节点状态（当前到第几个、哪些展开过）存在现有的本地进度里，key 按课程 id，刷新后回到原位。
- 键盘：`Enter` = 当前节点的主按钮；`↑ / ↓` 只在过去节点之间移动焦点；读屏器读“第 3 步，共 9 步，当前”。

### 4.3 测量题“就地验证”需要改的引擎逻辑（技术风险最高的一项）

现在：测量题只有在**整个目标电路**检查通过（`passed`）后才能测，读数按目标电路 + `set`（比如把旋钮设到 70%）算。

问题：LM358 的“不接反馈测输出”发生在第 5 步，电路还没完成，现有引擎不会给它读数。

方案：测量题加一个可选的 `after: <步骤号>`。
- 写了 `after`：在**这一步的步骤检查通过后**就可以测，读数取学生**当前的板子**（就是步骤检查已经认可的那个半成品）。
- 没写：行为和现在一样（整电路通过后）。
- 校验器（`npm run validate -- --readings`）要能在“参考答案的前 N 步”上算出读数，以确认期望范围。这需要从 `solution` 推出“第 N 步时的板子”——**第 1 期先做一个技术验证（spike）**：如果从 `solution` 推中间态不可靠，退路是在测量题里显式写中间态的 `set`/拓扑，或者这类“半成品读数”改成**预测选择题**（不读表）。
- 对没有分步的实验（67 个）不受影响：它们的测量都在整电路通过之后。

### 4.4 进度、e2e、无障碍、体积

- `scripts/e2e-lessons.cjs`、`e2e-bench.cjs` 现在按卡片走，要改成按节点走（点“下一步”而不是切标签）。
- `scripts/e2e-a11y.cjs` + `a11y-baseline.json`：新组件要过对比度和键盘检查。
- `check-bundle-size.ts`：拆解切片要**懒加载**（拆解的 SVG 很大，现在就是按页加载的），不能把 25 个拆解打进首包。
- 文档：`CHALLENGE_FORMAT.md` 新增 §17 `rail`；§16 `cards` 标为旧写法；`REBUILD_PLAN.md` 的写作规范 §4 改成“节点写作规范”；`AI_PROMPT.md` 同步。

## 6. 每一节课怎么做

**读法**：`①②③…` 是节点顺序。`🔍看 🔧搭 📏测 💡想 🎒带走` 是节点类型。方括号是这一步里长出来的内嵌块（§3 代号）。`Q1` 指这个文件 `measurements` 里的第 1 题（顺序同现在）。`步1–3` 指现有的第 1–3 个搭建步骤。“半成品”表示文件有 `start`（板上已经搭好一部分）。

**通用骨架**（各课按需增减）：

- **分步课程**（18 个）：🔍看器件外形 → 🔧搭（先做错 / 先看现象）→ 📏测现象 → 💡想明白（透视 / 推导）→ 🔧改对 → 📏测 → 🎒带走
- **实验 / 挑战**（67 个）：🔍看目标（抽屉自动展开一次）+ 预测 → 🔧搭 / 补线（整电路检查）→ 📏按**电路状态**分组测量（一个状态一个节点：“旋钮 0%”“S1→a”……）→ 💡想明白（推导块里代入**你自己的读数**）→ 🎒带走
- 计算型测量题（“用你的读数算 …”）一律**自带 B5 推导块**，推导的最后一行就是那道题的输入框。
