## 2. 「知识」模块：一个主题，一口气学完

**是什么**：课程按教材章节走，一个主题（比如 op-amp）分散在好几个 World、好几个单元、实验、拆解、计算卡片和理论章里。「知识」把**同一个主题**的东西按讲课的顺序串成**一条长的阅读流**，不跟课程进度、不用搭电路，从头读到尾就学完。

**入口**：课程里这个主题第一次出现的地方，放一个安静的入口（例如 3.1 LM358 课首：「📖 一口气学完 op-amp」）；「知识」页列出全部主题。

**怎么组成**：大部分是**引用已有的内容**（拆解的各层、理论单元的推导、计算卡片、要点、代表性理论题），只新写把它们串起来的过渡文字。所以要等课程编完再做（§4 第 4 步）。

## 3. 「练习」的内容在编课时一起整理

每一课的任务包（给执行 AI 的 brief）里写清楚这一课配的练习，编课时一起确认或补充：
- **挑战**：这一课之后可以自己做的不带分步的实验（现在 `course/worlds.json` 里同一节的 `challenge:` 项）；
- **理论题**：哪一章、哪几道（`chapter:` 项和单元里的 `problems` 块）；
- **计算卡片**：哪几张（计算卡片的 `lessons` 字段）；
- **知识主题**：这一课属于 §2.1 的哪个主题（以后做知识模块时按它归拢）。

这些清单以后都可以加，不影响课程本身。

## 4. 工作顺序

1. ✅ 定结构（本文档）、列出知识主题（§2.1）。
2. **整理任务包**：每课一份，含 §3 的练习清单和主题归属；共用一份写作与配图规范。
3. **执行 AI 按 World 编课程**（内容 + 配图）；新模型、新图种、新符号走“需求单”，由引擎这边统一做。
4. **编知识模块**：按 §2.1 把素材串成阅读流，补过渡文字。
5. **最后改界面**：导航收成 4 项（§1）、合并练习页、导入移进自由编辑，以及整体 UI 整理。
